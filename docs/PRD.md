# ThreadMind 产品需求文档

- 状态：Accepted
- 版本：MVP v0.1
- 日期：2026-08-26
- 平台：Android

## 1. 产品定义

ThreadMind 是一个个人关系与行动 Agent。用户提供一张聊天截图，也可以附加一段补充文字；系统理解对话上下文，找出可执行行动并生成可编辑、可确认的 Action Cards。行动成功后，系统结合当前上下文、用户的联系人与日历数据，以及可追溯的长期记忆，生成对用户有帮助的关系洞察和后续建议。

产品不是以“自动操作更多应用”为最终目标。Action Cards 用于将对话中的意图变成可靠事实和现实行动；洞察与建议才是主要交付内容。

## 2. 目标用户与问题

### 2.1 目标用户

MVP 面向经常通过即时通讯维持工作或私人关系、会从聊天中产生会议安排和联系人变化，并希望减少信息遗忘的 Android 个人用户。

### 2.2 用户问题

- 会议时间、地点和参与者散落在聊天中，容易遗漏或手工录入出错。
- 新联系人和联系人信息变化没有及时进入通讯录。
- 单次对话与过去互动、联系人背景及已做承诺彼此割裂。
- 通用摘要只能复述聊天，不能告诉用户下一步该做什么以及为什么。
- 自动化工具常在用户不知情的情况下推断或写入数据，缺少可控性和可追溯性。

### 2.3 核心价值

ThreadMind 将“聊天中发生了什么”“现在可以做什么”和“接下来值得关注什么”连成一个由用户控制的闭环：

> 理解上下文 → 确认行动 → 写入可靠数据 → 形成记忆 → 生成洞察 → 支持下一次判断

## 3. MVP 范围

### 3.1 包含

- 在 App 内选择并上传一张聊天截图。
- 从相册或聊天应用通过 Android 系统分享导入一张截图。
- 为截图附加可选补充文字。
- 云端 OCR、多模态上下文理解、实体识别和行动识别。
- 创建会议、创建联系人、更新联系人三类 Action Card。
- 卡片内编辑、缺失字段提示、低置信字段提示和逐卡确认。
- 使用 Android Calendar Provider 和 Contacts Provider 读取及写入设备已有账户。
- 执行结果回执，以及执行成功后的即时洞察和建议。
- 自动长期记忆与可查看、搜索、编辑、单条删除、全量清除的记忆中心。
- 提交记录、Action Card、执行回执、记忆和洞察的来源追溯。

### 3.2 不包含

- iOS、桌面端和 Web 端完整产品。
- 多用户、家庭或团队空间。
- 自动生成或发送聊天回复。
- 通用待办和项目管理。
- 每日、每周或主动推送式回顾。
- Google Calendar 或 Google Contacts API 直连。
- 无需用户确认的外部写入。
- 具体 Android UI 框架、后端语言、数据库、模型供应商或 memory backend 选型。

## 4. 核心用户流程

### 4.1 提交与分析

1. 用户从 App 内选择截图，或通过 Android 系统分享将截图发送到 ThreadMind。
2. 用户可以输入补充文字，例如“这是客户陈先生，我们在约下周见面”。
3. App 明确展示将上传到云端处理的内容，并允许用户取消。
4. 系统创建一次提交，完成 OCR、消息顺序理解、说话人识别、实体解析和行动识别。
5. 系统展示分析结果与 Action Cards。OCR 或说话人不确定时，相关依据和字段必须标为低置信，不能伪装为确定事实。

### 4.2 Action Card 审核与执行

每张卡片必须支持查看来源、编辑字段、取消和确认。确认只授权当前卡片的当前版本；用户编辑后，执行的是编辑后的快照。

#### 创建会议

字段：

- 标题（必填）
- 开始时间（必填）
- 结束时间或时长（必填）
- 时区（必填，默认使用设备时区但必须可见）
- 地点或线上会议信息（可选）
- 参与人（可选；若填写，必须关联到明确联系人或可识别地址）
- 备注（可选，允许保留来源摘要）
- 目标日历（必填；默认值必须可见且可修改）

如果日期、时间或时区存在歧义，系统必须要求用户在卡片内明确选择。检测到疑似重复会议时，必须展示冲突并再次确认，不能静默创建。

#### 创建联系人

字段：

- 姓名（必填）
- 至少一种可识别联系方式（电话号码或电子邮件，必填）
- 公司、职位、地址、备注等可选字段
- 目标联系人账户（必填；默认值必须可见且可修改）

创建前必须搜索可能重复的联系人。存在候选时，用户必须选择继续创建或改为更新已有联系人。

#### 更新联系人

字段：

- 目标联系人（必填且必须唯一确定）
- 建议变更的字段级差异（必填）
- 每个字段的旧值、新值及来源依据

姓名匹配本身不足以自动确定联系人。多个同名或近似联系人必须由用户选择。覆盖非空旧值时必须明确显示差异并再次确认；未出现在变更中的字段保持不变。

### 4.3 执行回执

每张已确认卡片产生独立执行回执，状态为：

- `succeeded`：外部写入成功，并保存目标记录 ID。
- `failed`：写入未完成，保存可理解的失败原因；不得生成虚假目标 ID。
- `cancelled`：用户取消或系统在写入前终止。

权限拒绝、目标账户不可用、系统 Provider 异常或数据验证失败时，卡片保持可恢复状态。重试仍需沿用或重新确认可见的卡片快照，不能后台静默重试写入。

### 4.4 洞察与建议

至少一张卡片成功执行后，系统即时生成一个 `InsightBundle`。没有成功行动时可以展示分析摘要，但不得伪装成“执行后洞察”。

洞察优先覆盖：

- 联系人是谁，以及与用户相关的已知关系背景。
- 本次对话相较历史互动出现了什么新信息或变化。
- 用户下一步可以采取什么行动，以及建议时间。
- 是否存在日程冲突、重复联系人、尚未兑现的承诺或信息不一致。
- 哪些内容是直接事实，哪些是模型推断。

每条洞察必须包含：标题、简明说明、依据列表、事实或推断标签、置信度，以及可选的建议行动和建议时间。洞察不得仅重复 OCR 文本，也不得把没有依据的性格判断、关系判断或敏感推断表达为事实。

## 5. Memory 产品规则

### 5.1 自动保存

系统自动保存从用户输入中提取的事件、偏好、关系信息和模型推断，不要求逐条确认。自动保存不等于无条件相信：每条记忆必须携带来源、事实或推断标签、置信度、敏感级别和时间范围。

以下内容可以形成长期记忆：

- 截图或补充文字直接表达的事实。
- 从上下文推断出的关系、偏好或意图，但必须标为推断。
- 用户对 Action Card 的编辑和确认结果。
- 外部写入成功后得到的权威记录标识和结果摘要。

以下内容不能作为事实记忆：

- 系统自己生成的洞察和建议。
- 未成功执行的拟议行动。
- 没有来源依据的补全内容。
- 仅因历史洞察曾经提到而再次生成的结论。

### 5.2 用户控制

记忆中心必须允许用户：

- 查看记忆内容、类型、来源摘录、事实/推断标签和创建时间。
- 搜索及按联系人、类型、时间筛选。
- 编辑错误内容；用户修正产生新版本并优先于旧推断。
- 删除单条记忆；删除后立即从在线召回中过滤，并异步清除派生索引。
- 清除全部记忆或删除账户数据。

记忆默认保留至用户删除。过时事件可以降低召回权重，但系统不得以“降低权重”替代用户要求的删除。

## 6. 权限、隐私与信任

- 截图、OCR 和补充文字仅用于完成本次分析以及生成有来源的结构化记忆。
- 原始截图不进入长期记忆，不用于训练；云端处理完成后删除。设备上的原文件由用户自行控制。
- 所有网络传输和持久化数据必须加密；服务端数据按账户隔离。
- Android 联系人和日历权限按需请求，权限说明必须对应具体用户动作。
- 没有当前卡片的显式确认，系统不得写入联系人或日历。
- 系统必须支持用户数据导出、单次提交删除、记忆清除和账户删除。
- 删除请求覆盖原始内容、结构化记忆、检索索引及其他可识别派生数据；法定安全审计若必须保留，只能保存最小化且不可用于个性化召回的记录。

## 7. 成功指标

MVP 试用阶段跟踪以下指标，具体质量阈值由首轮标注集和用户研究建立：

- 有效 Action Card 接受率及用户字段修改率。
- 从提交到完成卡片确认的时间。
- 外部写入成功率，以及因权限、数据缺失和 Provider 异常导致的失败率。
- 用户认为“有帮助”的洞察比例及建议采纳率。
- 洞察依据可追溯率和事实/推断标注正确率。
- 自动记忆的修正率、删除率及错误记忆再次召回率。

以下是上线前必须达到的安全不变量，而不是可权衡指标：

- 未确认外部写入次数为 0。
- 已删除记忆被在线召回次数为 0。
- 失败操作被记录为成功的次数为 0。
- 无依据内容被标记为事实的次数为 0。

## 8. 验收场景

### A. 创建会议

给定一张清晰截图，其中双方约定了下周三 14:00 见面；系统生成会议卡。用户补充标题、确认设备时区及目标日历后，会议成功写入，回执包含日历事件 ID，随后洞察提示相关联系人背景及会前准备建议。

### B. 创建联系人

截图包含姓名和电话号码，通讯录没有匹配项；系统生成创建联系人卡，用户确认后写入目标账户。缺少姓名或所有联系方式时，确认按钮不可用并明确提示缺失字段。

### C. 更新联系人

截图显示已有联系人的新公司和电子邮件；系统找到唯一联系人后展示旧值与新值。用户确认后仅更新所选字段。若存在多个同名联系人，必须先由用户选择目标。

### D. 歧义和重复

相对日期无法唯一解析、会议疑似重复、联系人匹配不唯一或非空字段将被覆盖时，系统展示具体歧义或差异，并阻止未经再次确认的写入。

### E. 权限和失败

用户拒绝联系人或日历权限、目标账户不可用或 Provider 返回错误时，执行回执为 `failed` 或 `cancelled`，不产生目标记录 ID，也不把拟议行动保存为已完成事实。

### F. 洞察可解释性

执行成功后的洞察同时引用本次对话、明确联系人数据和相关历史记忆。每条结论标明事实或推断及置信度；系统生成的建议不会成为下一轮的事实依据。

### G. 记忆纠错和删除

用户修改一条错误关系推断后，新版本优先参与召回，旧版本标记为已取代。用户删除该记忆后，后续洞察不再使用它。

### H. 数据删除

用户删除一次提交或全部账户数据后，相关原始截图、结构化记录、记忆、洞察历史及派生检索索引均不可继续召回。

## 9. 产品不变量

1. 没有确认，绝不外部写入。
2. 没有证据，绝不表达为事实。
3. 权威数据不能被低置信推断覆盖。
4. 洞察和建议不能反向成为事实记忆。
5. 用户删除的数据不能继续影响产品行为。
